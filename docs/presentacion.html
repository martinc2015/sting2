Agenda General

Propuesta de Equipo Consolidado

Equipo unificado con trayectoria y conocimiento acumulado

Proponemos conformar un equipo consolidado para abordar proyectos, iniciativas entre áreas y nuevos desafíos, reduciendo tiempos de adaptación y asegurando continuidad funcional.

Cobertura Multi-Área

Capacidad operativa inmediata para abordar requerimientos y proyectos de diversas áreas de la organización.

Forma de Trabajo Probada

Metodología y procesos estandarizados que ya funcionan, garantizando calidad, agilidad y predictibilidad.

Experiencia e Impacto

Años de trayectoria traducidos en soluciones eficaces, menor curva de aprendizaje y mitigación de riesgos.

Principio clave: No partimos de cero. Capitalizamos lo que ya funciona para transformar nuevos desafíos en soluciones reales.

Marco Scrum Aplicado

Calidad bajo ISO 9001

Procesos Estandarizados

Garantizan la trazabilidad total de requerimientos, la calidad continua del entregable y la mejora constante del proceso.

Gobernanza y Control de Ambientes

Hoja de control de ambientes TEST/UAT. Separación estricta de ramas Feature (F) y Release (R) por ticket con limpieza post-homologación.

Revisiones Exhaustivas de Código

Revisiones previas requeridas para paso a TEST y UAT. Prohibición estricta de cambios directos de código en ambientes de producción.

Políticas de Despliegue Seguro

Regla institucional: Evitar salidas a producción los días viernes, salvo casos excepcionales de urgencia crítica aprobada.

Proceso de Definición Funcional
1

Toma de Requerimiento

Análisis y Gestión

Objetivo

Capturar las necesidades funcionales y de negocio directamente de los usuarios clave o stakeholders.

Descripción

Reuniones de relevamiento, entrevistas y recopilación de documentación base para comprender el alcance integral.

Rol Humano (Analista Funcional)

Lidera la conversación, interpreta el contexto operativo del negocio, valida restricciones no técnicas y toma las decisiones de alcance con el cliente.

Asistencia de IA y Agentes

Asiste en la transcripción y estructuración de minutas, sugiere preguntas de clarificación y detecta posibles ambigüedades en el relevamiento.

Resultado / Entregable

Documento de Requerimiento inicial claro, sin lagunas de información y validado por el cliente.

Fase 1: Relevamiento y Captura
2

Creación de User Story

Análisis y Gestión

Objetivo

Estructurar los requerimientos en historias de usuario ágiles con criterios de aceptación precisos.

Descripción

Formulación estándar (Como / Quiero / Para) acompañada de casos de uso y criterios de aceptación estructurados.

Rol Humano (Analista & Equipo)

Revisa y convalida la lógica de negocio, define los casos límite, aprueba los criterios de aceptación y valida la viabilidad técnica.

Asistencia de IA y Agentes

Genera borradores estructurados de User Stories a partir del relevamiento, redacta escenarios de prueba y criterios en formato Gherkin (Given/When/Then).

Resultado / Entregable

User Stories detalladas, estimables y listas para ser priorizadas en el Backlog.

Fase 2: Especificación Ágil
3

Backlog y Planificación

Análisis y Gestión

Objetivo

Organizar, priorizar y estimar el trabajo a realizar en cada Sprint según el valor de negocio.

Descripción

Refinamiento de Backlog, asignación de puntos de historia (PH/Horas) y compromiso del equipo para el Sprint.

Rol Humano (Responsable de Proyecto & Equipo)

Define prioridades estratégicas, evalúa dependencias entre tickets, calcula la capacidad real y aprueba el plan de entregas con el cliente.

Asistencia de IA y Agentes

Asiste en el desglose de subtareas técnicas, sugiere estimaciones preliminares basadas en histórico y ayuda en el armado de diagramas de seguimiento.

Resultado / Entregable

Sprint Backlog priorizado, capacidad asignada y planificación acordada con el cliente.

Pipeline de Entrega Continua
1

Creación de Rama Feature

Desarrollo y Homologación

Objetivo

Aislar el desarrollo de cada funcionalidad para garantizar trazabilidad y control de versiones estricto.

Descripción

Creación de la rama Feature a partir del origen correspondiente, codificación de la solución y pruebas locales.

Rol Humano (Desarrollador)

Diseña la solución técnica, programa la lógica de negocio, asegura el desacoplamiento entre capas y valida el comportamiento en su entorno local.

Asistencia de IA y Agentes

Genera código base respetando la arquitectura del proyecto, asiste en la creación de consultas EF Core optimizadas y propone pruebas unitarias.

Resultado / Entregable

Código funcional en rama Feature aislada, testeado localmente y listo para integración.

Paso 1: Desarrollo Aislado
2

PR a Release

Desarrollo y Homologación

Objetivo

Integrar el desarrollo en la rama candidata de Release y abrir el canal de revisión técnica.

Descripción

Apertura formal del Pull Request hacia la rama Release correspondiente y etiquetado obligatorio a los DEVs del equipo.

Rol Humano (Desarrollador Autor)

Prepara la descripción del Pull Request, explica el impacto de los cambios, enumera los puntos clave a probar y solicita formalmente la revisión.

Asistencia de IA y Agentes

Genera resúmenes automáticos del diff de código, redacta el changelog y verifica preliminarmente el cumplimiento de directivas de nombrado y arquitectura.

Resultado / Entregable

Pull Request formalmente publicado, documentado y listo para revisión técnica por pares.

Paso 2: Solicitud de Integración
3

Aprobación y Code Review

Desarrollo y Homologación

Objetivo

Garantizar la calidad técnica, el rendimiento y la seguridad del código antes del despliegue.

Descripción

Revisión exhaustiva por parte de los desarrolladores del equipo, validando estándares ISO y ausencia de regresiones.

Rol Humano (Equipo DEV Revisor)

Analiza la robustez de la lógica, valida la no afectación a módulos existentes, sugiere mejoras y emite la aprobación formal del Pull Request.

Asistencia de IA y Agentes

Realiza análisis estático automatizado, detecta posibles cuellos de botella (queries N+1, falta de índices) y valida el cumplimiento de directivas STING.

Resultado / Entregable

Aprobación técnica formal registrada bajo ISO 9001 y merge seguro en la rama Release.

Paso 3: Control de Calidad por Pares
4

Pruebas en Ambiente TEST

Desarrollo y Homologación

Objetivo

Verificar la funcionalidad integrada y la estabilidad del sistema en un entorno controlado.

Descripción

Despliegue en el ambiente TEST correspondiente, ejecución de casos de prueba y reporte de incidentes si correspondiera.

Rol Humano (QA & Tester Funcional)

Ejecuta la matriz de pruebas funcionales, prueba escenarios de borde, valida la consistencia de datos y certifica el comportamiento esperado.

Asistencia de IA y Agentes

Genera datasets realistas para pruebas complejas, asiste en la ejecución de scripts automatizados y ayuda a diagnosticar logs de error en caso de fallo.

Resultado / Entregable

Ambiente TEST validado con reporte de pruebas satisfactorio, listo para promoción a UAT.

Paso 4: Validación en Entorno de Pruebas
5

Paso a UAT y Homologación

Desarrollo y Homologación

Objetivo

Obtener la validación formal y la conformidad del usuario final en el entorno de aceptación.

Descripción

Actualización del ambiente UAT, seguimiento formal en herramientas de gestión (Odoo) y pruebas directas de los usuarios clave.

Rol Humano (Usuario Final & Analista Funcional)

El usuario final valida que la funcionalidad responde a su necesidad operativa real; el Analista acompaña la sesión y gestiona la conformidad formal.

Asistencia de IA y Agentes

Genera instructivos y guías de uso rápido para los usuarios de UAT, resumiendo los pasos operativos clave de las nuevas pantallas.

Resultado / Entregable

Homologación formal firmada/aprobada en sistema de gestión, habilitando el paso a producción.

Paso 5: Aceptación por el Negocio
6

Homologación y Tag Versionado

Desarrollo y Homologación

Objetivo

Consolidar la versión en Master, generar el tag versionado y preparar el despliegue a producción.

Descripción

Merge de Release a Master post-homologación, creación de Tag SemVer inmutable, limpieza de ramas transitorias y despliegue según ventana segura.

Rol Humano (Líder Técnico & DevOps)

Supervisa el merge a Master, verifica la regla institucional de despliegue seguro (no viernes) y autoriza la puesta en producción definitiva.

Asistencia de IA y Agentes

Compila las Release Notes finales para el cliente, valida el checklist pre-deploy y documenta el historial de la versión para auditorías ISO.

Resultado / Entregable

Versión empaquetada, taggeada y trazable bajo ISO 9001, operativa en producción.

Paso 6: Release y Cierre

Reglas Clave de Calidad de Código

Modelos y Archivos de Configuración

  • · Modelos: Incluir únicamente archivos necesarios (.edmx, .diagram, classes, Context). Recordar incluir .csproj al agregar nuevas clases o vistas.
  • · Configuraciones: No subir archivos de configuración (app.config / web.config) salvo que sea imprescindible y esté verificado.

Estándares de Código y Gestión Git

  • · Buenas Prácticas: Usar enums en C# y constantes equivalentes en JS. Utilizar Entity Framework o Stored Procedures; prohibido SQL embebido.
  • · Trazabilidad: Documentar comentarios en lógica de negocio. Ciclo de ramas F → R (al finalizar, sólo una rama F y R por ticket).
Estándares de Ingeniería

Directivas STING Next (Ejemplo)

ARCHIVO MD, son las directivas básicas para que un agente ejecute siempre con un prompt

Intocabilidad de APIs Legacy: Prohibido modificar o refactorizar endpoints existentes de STING clásico. Cero riesgo de regresión.

Reutilización Eficiente: Reutilizar endpoints JSON existentes antes de crear nuevas estructuras.

Nomenclatura Obligatoria: Todo nuevo endpoint o acción debe usar el sufijo NombreApi_Next (ej: EliminarLotesMasivo_Next).

Notificación explícita: Informar previamente en el chat antes de crear una nueva API paralela.

Optimización Entity Framework: Aplicar lecturas no rastreadas AsNoTracking() en las consultas.
